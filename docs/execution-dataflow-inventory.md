# Execution/dataflow inventory before Authoring 0.3 design

Inspected the complete historical payment and case-management Canonical 0.1 snapshots at checkpoint `fab36ed`. This inventory distinguishes declared behavior from missing behavior. It does not infer business assignments.

| Domain / semantic IDs | Unambiguous historical declarations | Missing behavior decision |
| --- | --- | --- |
| Payment `CMD-RECORD` | Payment root, aggregate write envelope, positive-amount invariant, business/transient failures, idempotency policy, `EVT-RECORDED` emission | Operation input type; consumed input members; exact field write set; whether amount or summary changes; computed values; operation result construction |
| Payment `UC-TASK`, `STEP-CMD-RECORD` | Text input/output ValueObjects, one ordered command, atomic rollback transaction | Resource identity selection; text-to-operation binding; operation input construction; output value construction; required-input consumption |
| Payment `EVT-RECORDED` | Amount payload field, payment resource, at-least-once delivery policy | Payload value source and evaluation state; duplicate command/transition emission interpretation |
| Payment `TRANS-RECORD` | Draft → Posted, positive-amount guard, actor, command and event references | Guard state relative to mutations; event payload values; ordering of command effects versus transition and invariant checks |
| Payment `QUERY-TASKS` | Per-row output text projects `FLD-TASK-SUMMARY`, tenant scope, pagination and maximum 100 | Explicit operation-input contract; input-dependent query predicate; result consumption by use-case steps. Existing per-row projection itself is specified |
| Case `CMD-REVIEW`, `CMD-APPROVE`, `CMD-ARCHIVE` | Case aggregate write envelope includes case and child entities, failures, idempotency, distinct emitted events | Operation input/consumption; exact fields affected; whether children are created/updated; actual values; command result construction. Names do not establish review/approval/comment mutations |
| Case `UC-TASK`, three `STEP-CMD-*` | Review → Approve → Archive step order, one atomic rollback transaction, text input/output types | Selected case identity; each operation's input; prior-step result flow; output construction; which steps consume required text |
| Case `EVT-REVIEW`, `EVT-APPROVE`, `EVT-ARCHIVE` | Case-title payload field (nested ValueObject), delivery policies | Construction and evaluation state of every payload; command/transition duplicate interpretation |
| Case `TRANS-REVIEW`, `TRANS-APPROVE`, `TRANS-ARCHIVE` | Open → Reviewed → Approved → Archived, true guards, reviewer actor | Guard/effect/invariant ordering and event construction; state transitions do not imply mutations to child entities |
| Case `QUERY-TASKS` | Per-row summary projection, tenant scope, pagination and maximum 100 | Explicit operation-input contract and predicate; query result binding to later steps. Existing projection is specified |
| Both task `Filter` / `Search` | Query/output field, CONTAINS operator and String input type | Exact Query operation-input member receiving the filter value; pure predicate consuming it |
| Both `JOB-TASK` | Schedule/retry/timeout/idempotency and use-case reference | Required use-case input and selected resource for a scheduled invocation; the schedule cannot invent task text or resource identity |
| Both compensation support | Explicit compensating-command references are possible; these domains use STOP | Input/resource binding of a compensating operation; never derive inverse assignments |
| Both security/privacy | Policies, permissions, tenant scope, classifications, retention/hold declarations | New dataflow must preserve these gates; projecting classified state to less restrictive outputs needs explicit rejection/authorization, not name matching |

No operation parameters can be inferred from global Parameters: Parameters are explicit semantic constants, distinct from invocation values. Existing query projection and workflow topology remain meaningful historical contracts; their presence cannot fill the missing command and use-case behavior. Authoring 0.3 fixture decisions must cover every row above or explicitly reject unsupported invocation forms.

The historical declarations also leave these non-operation execution details bounded rather than executable. They must not be filled by a target assumption: no command declares creation of payment/case/member/organization or child records; no query declares a total ordering or tie-breaker for its paginated relation; ANONYMIZE lists fields but not replacement values (`FLD-AMOUNT` or `FLD-NOTE`); CLOSED retention names a trigger without binding an application timestamp; declared failure categories do not map every infrastructure exception to a business failure code. The 0.3 reference decisions explicitly operate on existing roots and retain these original obligations. They do not manufacture CRUD, privacy replacement values, closure timestamps, transport error mappings or pagination ordering. Full target admission must continue rejecting behavior it cannot derive. This operation/dataflow successor is not evidence that every later target capability is now specified or implemented.
