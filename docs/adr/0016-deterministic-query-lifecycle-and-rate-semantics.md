## Proposed canonical meaning

Query `orderBy` is an ordered array of exact Field reference and ASC/DESC keys. It is not a set. Keys belong to the Query resource and cannot repeat. Nullable keys explicitly declare `nulls: FIRST|LAST`; optional keys separately declare `absent: FIRST|LAST`. Absence and null are distinct. Irrelevant presence flags are rejected. Placement is independent of ASC/DESC; direction reverses only comparison of present, nonnull values. Scalar String/Identifier comparison is Unicode scalar lexicographic, case-sensitive and without normalization. Numeric types compare exact numeric values; Boolean false precedes true; Date/Instant compare their temporal values; Named uses its declared ordered scalar base. Lists, Sets and ValueObjects have no inferred comparator.

A paginated query requires a total deterministic order. The bounded implementation requires the complete resource identity as its explicit final key suffix. Independent uniqueness proofs other than the complete declared identity are not implemented in this proposal. No target may silently append keys. Ordered precedence is preserved in canonical bytes. The reference choices are Payment `FLD-PAYMENT-ID ASC` and Case `CASE-ID ASC`.

DataLifecycle `anchor` explicitly selects CREATED_COMMIT or CLOSED_COMMIT. CLOSED_COMMIT names the exact StateMachine and a nonempty set of closing States, `instant: COMMITTED_ENTRY` and `terminal: true`. The machine resource equals the lifecycle resource, every state belongs to that machine and is terminal. A CLOSED policy without a bound DataLifecycle anchor is invalid. Retention and deletion still use the same trigger. The anchor is the **successful transaction-commit instant entering a declared closing state**; rollback establishes no anchor. It is trusted operational state derived from the semantic transition, not an application/user timestamp field. Entry is measured against pre-transaction state; creation directly in a closing initial state is entry at creation commit. Reobserving the same closed state does not reset the anchor. Terminal closure precludes later reopening in this bounded contract. CREATED_COMMIT means successful resource-creation commit, with no guessed application field. Implementations unable to establish the defined commit fact must reject rather than substitute statement-start or wall-clock-before-commit time.

DeletionPolicy `anonymizationEffects` has exactly one entry for every field in ANONYMIZE `fields`, and no entries for other modes. REMOVE makes an optional member absent. NULL writes explicit null only to Nullable. REPLACE supplies an explicit constant `{type, value}` of the exact semantic Field type, including currency/precision/nominal identity/refinement. No arbitrary source-dependent pseudonymization is added. Foreign, identity and tenant fields are forbidden. Required nonnullable fields cannot be removed or nulled. Retained field/storage constraints and WRITE invariants remain applicable after disposal; invalid staged disposal fails atomically, without fallback replacement. Textual Constraint requirements remain outstanding obligations, not invented executable predicates. Where a constant alone disproves an invariant, validation rejects it; other record-dependent checks execute against the full proposed post-disposal record. An active LegalHold blocks all effects, including anonymization, unless the current-action release rule below explicitly authorizes that transaction.

RatePolicy `algorithm` explicitly selects TOKEN_BUCKET with CONTINUOUS_RATIONAL refill, FULL initial capacity, AUTHORIZED_INVOCATION charge, CHARGE replay and NONDECREASING semantic clock. Existing `requests`, `windowSeconds`, `burst` and ACTOR/TENANT partition fields retain their values but now have exact proposed algorithmic meaning. Each policy/tenant/(actor when ACTOR) partition starts with `burst` tokens at its first authorized invocation. Between invocation instants, refill by `elapsedSeconds × requests / windowSeconds`, capped at `burst`. Arithmetic is exact rational, with no floating-point rounding. Admit iff tokens >= 1, then consume exactly one. A rate-denied invocation consumes none; unauthorized invocations neither create nor charge a bucket. Authorized invocations count even when business execution later fails or idempotency replays a result. Commands and Queries are invocation sites; a UseCase does not add an undeclared extra charge. Clock reversal fails safely without admission/refund; storage eviction may not manufacture tokens. Equivalent implementations may evict a fully replenished idle bucket only when reinitialization is observationally identical. Atomic ordering of concurrent requests is a target implementation obligation. This is **not** a fixed/sliding-window choice made by Spring. Future rate-policy deployment revisions require explicit state-migration review rather than an inferred reset.

The reference proposal is exactly 100 tokens replenished per 60 seconds, capacity/burst 10, ACTOR partition. Thus ten simultaneous requests can be admitted initially, the eleventh is denied, and one token replenishes after exactly 0.6 seconds. Capacity remains ten after a long idle period. Admission at 0.599999999 seconds differs from admission at 0.6 seconds; tests use exact supplied integer nanoseconds, not a host clock. This choice requires human review.

INTERVAL Schedule gains explicit UTC `anchorInstant`: occurrence n is anchor + n × intervalSeconds, n=0,1,...; no first-run time is inferred from process startup. Migration of an unanchored INTERVAL requires review. Neither reference fixture is changed to INTERVAL. LOCAL_DAILY occurrence semantics remain pinned local civil date/time, IANA tzdb, explicit gap and overlap policies. Per-date determinism does not choose Job activation, missed-occurrence catch-up or credential semantics.

The accepted `retry_horizon` helper already establishes total attempts and the capped exponential algebra. Propose making the remaining timing choices explicit in RetryPolicy: `attemptCounting: INCLUDING_INITIAL`, `delayBasis: AFTER_FAILURE_COMPLETION`, `jitter: NONE`. Delay after failed attempt i, with initial attempt numbered 1, is min(initialSeconds × multiplier^(i-1), maxDelaySeconds), for i=1..maxAttempts-1. `maxAttempts` includes the initial attempt. No retry after the final attempt, no jitter and no retries of undeclared/nonretryable failures. The declared timeout-plus-delay horizon must remain within job and command idempotency windows. The complete successor extension below defines the idempotency window anchor.

## Complete successor extension: I-01, D-01, J-01, H-01, DC-01

All rules below are **PROPOSED / HUMAN REVIEW REQUIRED**, in the same Authoring 0.4 / Canonical 0.3 / ChangeSet 0.3 successor. They resolve the five known questions at the proposal level; no accepted contract or production capability changes.

### Idempotency lifecycle

IdempotencyPolicy explicitly requires `windowAnchor: COMMITTED_RESULT` and `inFlight: RETURN_IN_PROGRESS`. Before effects, an authorized, rate-admitted invocation atomically claims an identity containing the exact policy ID/revision, tenant, applicable scoped typed resource identity, exact operation ID/revision and canonical typed semantic key. A Job additionally includes its exact Schedule ID/revision and scheduled occurrence instant, never worker startup time. Bind the canonical digest of the exact input type and normalized semantic input value, including nominal references; equivalent numeric spellings do not create different inputs.

An existing active identity with different input returns CONFLICT. Same input in IN_FLIGHT or indeterminate recovery returns IN_PROGRESS without effects, waiting, events or target-selected blocking. Only the reservation owner executes. Successful result, domain effects, event intents and reservation finalization commit atomically within the applicable semantic transaction boundary. Replay returns the committed typed result, with no repeat effects/events. The replay interval is half-open: `commitInstant <= invocationInstant < commitInstant + windowSeconds`. At the exact deadline a new invocation may claim anew, including with different input. There is no deadline for pending/indeterminate reservations. Definitive rollback proving no committed effect may release a claim; process death, lost leases or elapsed time are not that proof. Recovery finalizes a proven commit using its original commit instant/result or clears a proven no-effect rollback; uncertainty retains IN_PROGRESS/CONFLICT indefinitely. This deliberately favors duplicate-effect safety over availability. Multi-boundary UseCases retain ADR-0015's boundaries; this proposal does not invent all-or-nothing distributed commit or a global replay wrapper over them.

Durable storage, fencing, atomic locks, commit-fact acquisition and reconciliation are target mechanisms requiring crash/concurrency evidence. A process-local cache cannot satisfy production idempotency. The pure reference state is a serializable transition witness with a trusted atomic-serialization premise, not a durable implementation.

### Delivery and ordered occurrences

DeliveryPolicy requires `windowAnchor: EVENT_COMMIT` and `occurrenceOrder: COMMIT_STEP_EMISSION_SEQUENCE`. An event is eligible only after the successful semantic transaction commit; rollback creates no occurrence. Its half-open eligibility window is `[eventCommitInstant, eventCommitInstant + windowSeconds)`. At the deadline an outstanding AT_LEAST_ONCE obligation becomes UNSATISFIED; a send or late acknowledgement cannot retrospectively satisfy it. Attempts may repeat before that boundary until acknowledged. AT_MOST_ONCE consumes its sole externally visible attempt before observing its outcome; failed or uncertain outcome never permits a resend. An acknowledgement is unnecessary for this guarantee, and an attempted uncertain send remains ATTEMPTED, not acknowledged. An unattempted occurrence at expiry is also recorded as an unfulfilled delivery obligation. There is no exactly-once transport claim.

Command requires `emissionOrder: DECLARED_BINDING_SEQUENCE`. In this successor alone, `eventBindings` is a semantically ordered array preserved by canonicalization. Payload field construction remains field-keyed/unordered. Duplicate binding of the same event semantic identity within one operation is ambiguous and rejects; event IDs detect ambiguity and never sort occurrences. Within a transaction, order is UseCase execution-step position then operation emission position. Across commits for the same tenant/aggregate typed identity, the successful semantic commit serialization sequence precedes those positions. Equal timestamps require the established commit sequence, never a lexical event ID or wall-clock tie breaker. A target unable to provide that sequence must reject the capability.

PER_AGGREGATE prevents a later occurrence overtaking an earlier pending unexpired occurrence for the same instance. Acknowledgement, completed AT_MOST_ONCE attempt, or recorded expiry releases that ordering barrier; an unsatisfied expired predecessor remains recorded as such. NONE has no cross-event ordering guarantee. Transport retries are independent of command replay. Deduplication retains each occurrence's identity through at least its complete delivery window, including retries; an IdempotencyPolicy used for deduplication must have `windowSeconds >= delivery.windowSeconds`. A consumer's first receive cannot shorten the producer's deadline coverage. Transport/provider and outbox mechanisms remain target-profile decisions.

### Job recovery

Job requires `missedOccurrences: SKIP|RUN_LATEST|CATCH_UP` and `catchUp`. For SKIP and RUN_LATEST, `catchUp` must be null. For CATCH_UP it is a closed record with `maxOccurrences` in 1..10000 and explicit `overflow: REJECT|DROP_OLDEST`. No unbounded replay or inferred default exists.

At a trusted scheduler recovery/activation instant, missed occurrences are exact schedule occurrences strictly earlier than activation that have not started. An occurrence exactly at activation belongs to normal scheduling; future scheduling continues from the exact schedule. SKIP executes none of the missed occurrences. RUN_LATEST executes only the latest missed occurrence once before future scheduling resumes. CATCH_UP executes chronologically. If the number exceeds the bound, REJECT executes none and exposes overflow for explicit resolution; DROP_OLDEST explicitly discards the older excess and executes the latest bounded suffix chronologically. Occurrences already started use idempotency/recovery rather than being reclassified as not started. Scheduler persistence must distinguish those facts. The reference payment and case proposals use **SKIP / HUMAN REVIEW REQUIRED**. Job identity includes the schedule occurrence; a retry retains it and a legitimate next occurrence differs.

### Current-action LegalHold release

LegalHold requires `releaseMode: CURRENT_LIFECYCLE_ACTION`. Evaluate its condition for every lifecycle action. An active condition blocks deletion and anonymization unless the invocation explicitly requests release and proves the exact declared Permission for the same tenant, resource instance, action and transaction. Permission possession alone never bypasses the hold. All other disposal authorization and invariant checks still apply. Multiple active holds each require their own exact authorization.

The authorization applies only inside the current lifecycle action transaction: it creates no durable clearing, transferable token or reusable override. Audit the authorization with semantic identifiers and action/transaction scope, without prior field values, atomically with successful disposal. Rollback produces neither successful release/disposal nor a successful audit assertion; any independent failed-attempt security audit must be explicitly marked unsuccessful and value-free. Every later action reevaluates the condition and needs a fresh request/authorization if still active. Literal-true fixture holds therefore block normal disposal and permit only an explicitly authorized current-action override. This fixture meaning is **HUMAN REVIEW REQUIRED**.

### Non-domain observability redaction

DataClassification requires `redactionScope: NON_DOMAIN_OBSERVABILITY`. Covered surfaces are logs, traces, diagnostic/error metadata and audit-value representations, including equivalent derived raw representations. NONE imposes no additional redaction obligation; other applicable policies still govern. MASK discloses neither raw value nor prefix, suffix, length or reversible transformation; a fixed non-reversible marker plus semantic identifiers is permitted. The exact textual marker belongs to a target profile and is outside the field's semantic type. OMIT emits no field value or equivalent derived raw representation. Implementations must prevent raw values entering metadata, stack traces, request bodies, SQL diagnostics or exporter attributes before redaction.

Typed business/API/Event projections retain their exact types and values, subject to authorization, classification and export rules; redaction does not silently replace them. Future presentation/output masking needs separate explicit semantics. Value-free existing audit records conform. SENSITIVE MASK and SECRET OMIT fixtures require complete non-disclosure on all covered surfaces. Generated diagnostics tests verify the existing value-free error/log path; the pure reference projection tests all four surfaces. These are bounded evidence, not proof of production tracing/exporter configuration or full DataClassification capability.

### Canonical cross-cutting invocation protocol

Command, Query and UseCase explicitly require `invocationOrder: AUTH_SESSION_AUTHZ_TENANT_RATE_IDEMPOTENCY_TRANSACTION_ATOMIC_COMMIT_DELIVERY`. This closed value defines:

1. Authenticate and validate session.
2. Authorize exact operation/resource/tenant; for Job this includes its explicit execution principal.
3. Admit/charge each applicable RatePolicy at the actual Command/Query invocation site.
4. Resolve idempotency reservation, replay, conflict or IN_PROGRESS where declared.
5. Execute the semantic transaction with tentative result, effects and ordered event intents. Lifecycle disposal evaluates holds and explicit current-action release before its effects.
6. Atomically commit domain state, successful result, event occurrences and idempotency result where applicable; rollback preserves none of that boundary's tentative output/events.
7. Make committed event occurrences eligible for independent delivery.

A UseCase is the coordinator and does not charge an undeclared extra bucket. Prior committed boundaries are not silently undone by a later denial/failure. Unauthorized invocations create neither rate nor idempotency state. Rate denial happens before reservation. Replays consume rate capacity under the proposed CHARGE rule; denial may therefore precede replay. Replay creates no new events. Transport retries do not reinvoke or recharge the command. Job schedule identity feeds idempotency. Hold-authorized anonymization audit carries no sensitive prior values. This order is a business-visible **HUMAN REVIEW REQUIRED** decision, not a Spring filter default.
