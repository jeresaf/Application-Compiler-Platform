LOCAL_DAILY is deterministic for a specified date: form local civil date+time, use exact pinned IANA rules, round-trip both folds, SKIP/REJECT gaps and EARLIER/LATER/REJECT overlap. `execution_semantics.local_occurrence` implements that accepted algebra. Unknown infrastructure failures cannot enter retry solely because they were caught by a generic exception handler.

## Capability honesty review

Reviewed every manifest entry at the accepted checkpoint. Exact type/record, explicit command/query/use-case effects, same-root STOP transaction, MFA/session and bounded relation capabilities have implementation and generated component tests within their declared constraints. They remain bounded foundations, not whole-application acceptance. Relation real PostgreSQL tests must continue proving tenant FKs, max uniqueness, deferred minimum cardinality and RESTRICT deletion.

The exhaustive [machine-readable capability inventory](../targets/spring-vue-postgres/evidence/capability-honesty-audit.json) covers **every manifest entry**, with status, exact constraints and implementation/test sites. `worker/capability_contract.py` is the runtime source of those declarations; a boundary test compares the full inventory with the real worker manifest and its real negotiation blockers. No generic "bounded model" label stands in for a restriction.

`METADATA` entries now explicitly report OBLIGATION_ONLY: retained provenance or requirements with satisfaction OUTSTANDING. This includes quality/accessibility/responsive/observability requirements, backup/recovery, textual Constraint and Service grouping. None certifies runtime satisfaction. Eleven general UI families (Screen, Form, InputControl, Table, Filter, Search, Wizard, WizardStep, Action, ViewState, PermissionBoundary) are now UNSUPPORTED: the existing synthetic component shell/tests do not establish every declared message, table projection, multi-step navigation, input binding or exact permission boundary. Declared Failure execution is also UNSUPPORTED: target exception mapping does not implement operation-declared BUSINESS failures. These 12 overclaims are intentionally narrowed, not waived.

Expected-blocker contract **1.1.0** explicitly adds these 12 blockers to both exact snapshots, for **27 blockers each**. Version 1.0.0's historical report remains preserved. This is an intentional engineering capability correction under Part O, not a new semantic approval. Any other added/disappeared blocker still fails. Core constrained execution, typed records, scoped authorization/session, workflow and relation claims retain explicit restrictions; negotiation now additionally rejects missing WRITE invariant attachments, multiple machines per resource, competing same-command transitions, nonscoped/composite operation roots and unsupported policy expressions.

The application-enforceable subset now generates READ audit for authorized selected rows and WRITE audit for explicitly assigned fields, using the exact classification mode. Per-field audit records contain semantic IDs and actor/resource identities, never field values. They commit/roll back with the operation. General operation audit is separate and does not certify a classification requirement. Query transactions permit these audit writes. Export helpers enforce DENY or the exact declared permission; no export route is advertised. Safe error mapping and logging configuration suppress raw request/JDBC values. Full MASK output semantics and infrastructure encryption remain unimplemented/OUTSTANDING.

An unreleased LegalHold guard evaluates the exact condition and blocks; an exact release-permission check cannot itself release the hold. There is no active disposal worker or authorized release-lifetime path, and no lifecycle capability is admitted. Generated component tests prove that even successful permission checking does not bypass the literal-true hold. Deployment encryption/TLS/destruction, availability, quality and manual accessibility evidence remain OUTSTANDING.

The versioned [failure mapping](../targets/spring-vue-postgres/templates/backend/src/main/resources/acp-failure-mapping.json) maps exact SQLStates and exact runtime exception classes. Unknown failures return safe INTERNAL_ERROR; mapping never invents BUSINESS or grants retry. Known deadlock/serialization faults are TRANSIENT candidates, but a live retry runtime is not admitted and the response remains retryable=false. Generated tests exercise recognized/unrecognized SQLStates, wrappers and message secrecy. Declared semantic Failure handling stays blocked until actual exact runtime sites and tests exist.

All 11 pending capability families remain unsupported until the exact constrained runtime, generated tests and safe failure behavior exist. The audit finds additional canonical gaps I-01, D-01, J-01, H-01 and DC-01, so complete idempotency, delivery, live jobs, release and classification must not be claimed merely because Parts I–N allow continuation **if** semantics are complete. Safe independent work is limited to application audit/export/logging, an unreleased hold barrier, exact failure mapping and reference schedule/retry algebras; none may enable guessed dependent lifecycle/rate behavior or bypass the expected-blocker contract.
