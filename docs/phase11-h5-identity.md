# Phase 11 H5 cryptographic identity

H5 is an additive, source-bound qualification generator over H1. Historical trusted-JWT component tests remain separate. Its generated Spring Security resource server uses the locked Nimbus JOSE implementation for genuine RS256 signature verification. Canonical authorization, tenant storage, ownership, session freshness, revocation and MFA checks remain active. Issuer role claims do not grant Canonical permissions.

Run `PYTHONPATH=tooling:. <SDK-python> -B -m engineering.identity.run --workspace <new-disposable-directory>` with the existing pinned Maven/npm inputs. The dedicated H5 workflow uses Ubuntu 24.04, CPython 3.14.7, Node 24.21.0 and Java 21. It rejects missing security cases, wrong source/generator identities and unverified cleanup. Failure stops qualification; no retries or skips are used to obtain success.

The host supplies `ACP_IDENTITY_CONFIG` and its SHA-256 through `ACP_IDENTITY_CONFIG_SHA256`. The closed `acp-bound-jwt/1` configuration binds issuer, audience, RS256, zero clock skew, tenant mapping, Canonical role assignment, access-token type and the absolute public JWKS path/hash. Requests cannot override configuration. Unknown profiles, altered configuration, missing/substituted key files and untrusted token keys fail closed. No token-provided URL is fetched.

The disposable HTTPS issuer publishes public keys and issues signed access tokens. Its ephemeral TLS CA is explicitly trusted by the fixture client; TLS validation remains enabled. Signing keys remain in memory; the temporary TLS private key is outside the execution/evidence directory and is removed. Tokens and private keys must never enter downloadable evidence. Maven environment dumps are removed in private temporary log staging while plugin-realm diagnostics and command failures remain intact. The runner scans actual issued credentials before creating a redacted public export. CI uploads only that export after successful qualification.

Rotation is deliberately bounded: both public keys are pinned before overlap; the new key signs while the old remains accepted. Retirement requires an explicitly repinned public key set/configuration and a fresh application process. A publisher outage does not invalidate already pinned public keys, but local key-source loss or substitution rejects authentication even for previously valid tokens. This is not a remote revocation service or production trust enrollment.

Interactive principals bind to Canonical Actor subject identities and tenant fields in PostgreSQL. This bounded profile accepts subject, tenant and session identifiers matching `[A-Za-z0-9:_-]{1,128}` and scoped Actor subject entities with one identity field; unsupported bindings fail closed. Unknown or incorrectly bound principals are denied. Supported business journeys cover two tenants, CREATE, review/approve/archive, documents, reporting, audit history and job-status reads. Invalid credentials produce 401; authenticated authorization/session violations produce 403; cross-tenant resource reads preserve the established 404 contract.

Workers receive no fabricated interactive JWT. In explicitly disabled development polling mode the H5 bootstrap does not eagerly resolve the legacy interactive principal port. Active or production polling retains the existing requirement. The separate integrity worker retains its existing explicit host service context. Cryptographic service enrollment and production service-account authority remain unsupported and require an independent deployment decision.

Production still requires approved issuer ownership, authenticated tenant/principal lifecycle, key custody, rotation/revocation operations, TLS/ingress, service identities and operational monitoring. This fixture establishes engineering behavior only. Phase 11 remains in progress; Phase 12 has not started. Release closure remains blocked and operational security is not established. The historical intermittent H3 CREATE 500 remains unresolved and is not attributed to or fixed by H5.
